# CLAUDE.md — working notes for lps2

LPS(2): a clean-room reimplementation of the LPS engine in SWI-Prolog, plus (later) an
LLM-facing agent layer. The plan of record is **`docs/LPSplusLLM.md`** — read it before
doing anything substantial; it defines milestones M0–M11 and the conformance obligation.

## Hard rules

1. **Never write inside `legacy_lps1/`.** Running the legacy engine on a file *does* write
   next to it (`foo.pl` → regenerated `foo.pl_.P`, and `make_test` → `foo…lpst`). The
   harness therefore always copies programs into `build/` first. If `git status` ever shows
   a modified file under `legacy_lps1/`, `git checkout --` it.
2. **Clean-room boundary.** The engine is written from the plan and from observed behaviour,
   not by transliterating `legacy_lps1/engine/interpreter.P`. The exceptions, stated in
   §I.4, are *interface specifications*: the operator table and the internal predicate
   vocabulary, which we deliberately copy.
3. **Core purity (§I.2.4).** Once `src/core/` exists, nothing in it may reference threads,
   sockets, HTTP, `process_create`, `shell`, `get_time`, or foreign predicates. I/O lives at
   the edges. A CI lint enforces this.
4. Milestone gates are real: M4 (conformance) gates all later work.

## Running the conformance harness

```sh
./myswipl.sh -q -g "consult('conformance/runner.pl')" -g "runner:main([ARGS])" -t halt
```
with ARGS a list of atoms, e.g. `['--only','goat','--variants','none']`. Flags:
`--only Substring`, `--variants a,b,c`, `--limit N`, `--jobs N` (keep at 1: concurrency
perturbs the legacy engine's per-phase time limits), `--time-limit Seconds` (default 120),
`--extended` (adds the six slow real-time tests kept in `utils/moreTestResults`),
`--upstream` (cross-check our verdict against the legacy engine's own `run_test`),
`--report-only` (re-render the report from `build/results.pl` without re-running),
`--no-report`.

A full run is ~35 min single-job; results land in `build/results.pl` and
`docs/conformance_report.md`. Per-run artefacts (program copy, `engine.log`, produced
`.lpst`, `status.pl`) stay in `build/work/<slug>/<variant>/` — read those first when a test
misbehaves.

## Running SWI-Prolog

```sh
./myswipl.sh -g "consult('conformance/runner.pl')" -g "main" -g halt
```
`timeout(1)` is **not** available on this macOS box — use SWI's `call_with_time_limit/2`
inside the child, or `process_wait/3` with a `timeout` option in the parent.

## The legacy engine, in one paragraph

`legacy_lps1/utils/psyntax.P` is the entry point; consulting it loads
`engine/interpreter.P`. A program in surface syntax (`foo.pl`, `foo.lps`, `foo.lpsw`) is
translated by `psyntax` into an internal-syntax file `foo.pl_.P` (facts: `reactive_rule/2`,
`l_events/2`, `l_int/2`, `l_timeless/2`, `d_pre/1`, `initiated/3`, `terminated/3`,
`initial_state/1`, declarations). `interpreter:go(File, Options)` runs that internal file.
`psyntax:golps(Source, Options)` does translate-then-run in one step. Golden test files are
named after the *generated* file: `foo.pl_.P.lpst`.

Options that matter: `dc` (the resolution path we reimplement — everything upstream is
tested with it), `make_test` (record a trace and write it as a `.lpst`), `run_test` (load a
`.lpst` and check against it). `make_test` + `run_test` are mutually exclusive in practice.

## The conformance contract (§0.2 — read it)

A `.lpst` is a Prolog fact file with `lps_test_result(Stage,Cycle,Count)` and
`lps_test_result_item(Stage,Cycle,Term)` for `Stage ∈ {fluents, events, composites}`.
Comparison is: exact item count, then `sort/2` on both sides and `variant/2`. So order
within a cycle is free, but *cycle alignment, item count and term shape up to variable
renaming* are all exact. A program that is supposed to fail carries
`lps_test_result_item(end,-1,failure)`. This is **trace equivalence, not semantic
equivalence** — the main technical risk in Part I.

## Conventions

- Prolog source: 4-space indent is *not* used upstream; follow the local file's style.
  New code in `conformance/` and `src/` uses standard SWI module headers with explicit
  export lists and `%!`-style predicate docs.
- Reports are generated, not hand-edited: `docs/conformance_report.md` is written by
  `conformance/runner.pl`. Hand-written analysis goes in `docs/selection_spec.md`.
- Prefer subprocess isolation when running the legacy engine: it uses global state,
  `halt/0` on some errors, and per-step `call_with_time_limit/2` (default 0.75 s/step).
